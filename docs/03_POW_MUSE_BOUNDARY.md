# POW / Muse boundary

## Hard rule

A POW query should remain meaningful if `user_id` is deleted from the system.

## POW owns objective state

Examples:
- typical repair spread for model X
- part scarcity
- skill requirement
- qualification/occupation mapping
- market demand by geography
- supplier concentration
- power headroom
- company exposure
- security price/book assimilation
- historical event propagation

## Muse owns personalized action

Examples:
- can *I* legally/safely perform this repair?
- should *I* buy this listing?
- which job should *I* take?
- which training should *I* enrol in?
- is this opportunity inside *my* budget/radius/calendar?

## Trading boundary

POW can say:
“Component scarcity rose before the exposed security repriced in similar historical events.”

A separate user/trading layer decides:
- whether to trade
- direction
- position size
- execution
- portfolio risk

POW remains the measurement substrate.
